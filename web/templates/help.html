使用说明

本程序在 Polymarket 奖励市场挂被动 BUY 单。它不保证盈利；下单和钱包风险始终由使用者承担。

开始前

  • 首次打开设置登录密码。私钥只以加密形式保存在本地，每次启动都必须登录解锁。
  • 在“配置”中先创建模板并启用至少一个档位模块；没有匹配的档位时程序不会挂单。
  • 导入钱包后先使用手动扫描和观察模式验证参数，再启用实盘。

运行逻辑

  1. 扫描奖励市场并按模板的价格、价差、结算时间和品类筛选。
  2. 只挂 GTC post-only BUY 单；单子会因价差、奖励或结算状态变化而被撤销。
  3. 成交后只暂停已成交 token/side 的新 BUY；同市场对侧奖励 BUY 仍可继续挂单、维护和赚取奖励。
  4. 普通二元市场一旦同时持有 YES+NO，完整集合会先 Merge。数量不等时先 Merge 配对部分，只让单边 residual 进入离场逻辑。
  5. 普通单边仓允许两条路径并存：对侧 reward BUY 继续等待自然配对，本侧 maker SELL 同时按成本保护退出；先成交的一条路径生效。
  6. 严重亏损时比较 direct SELL 与受价格保护的 FOK 补对侧 + Merge，只在后者超过优势下限、能少亏更多时选择补全；FOK 未确认成交或结果不确定时不会假设已经配对。
  7. 成本无法从实际成交重建时，程序会跳过而不会猜测 Data API 平均价。

Merge 安全边界

  • 仅处理普通二元市场；negRisk 或多结果市场不会自动 Merge。
  • 自动 Merge 仅适用于 POLY_1271 Deposit Wallet（Type3），并且需要显式配置 Builder/Relayer 授权。Type1/Type2 仍可正常做市，但自动 Merge 不适用。
  • 提交前会撤销冲突 SELL 并重新确认仓位；Relayer 确认前不当作已合并。
  • 完整配对始终保留给 Merge，不会被低余额清仓或常规离场拆散。
  • 首次 Merge 会在同一 Deposit Wallet 批处理中给官方适配器设置 CTF ERC-1155 授权。

成交后库存处理（Fast-Exit V2）

  • Reward BUY 是为了赚做市奖励：成交后的持仓不是方向性投资，程序会立即 开启「库存退出周期」，尽快把库存转回抵押品。
  • 完整集合先 Merge：普通二元市场的 YES+NO 配对永远优先合并； 低余额、结算、紧急退出都不会拆散配对。
  • 单侧残差三条路线（每次都先算两条回收再决定）： ① 受保护直卖——按买单簿可执行深度计价，以吃满数量所需的最差价位为限价下 FAK 市价限价卖单，绝不无保护滑点； ② FOK 补对侧 + Merge——回收按签名 FOK 的最差限价计算，只有比受保护直卖 至少多回收「补边 Merge 最低优势」（默认 0.01 USD）才选，成交后立即判断， 不必等严重亏损； ③ Maker 逃生窗口——默认最多 30 秒，窗口内本侧挂 Maker 卖单（可低于成本、 绝不穿价），对侧 Reward BUY 限量到未配对残差，超时后回到受保护直卖。
  • 紧急退出阈值（原止损项）：达到阈值后不是无脑市价卖，而是跳过 Maker 等待、立即比较受保护 Market 与 FOK+Merge，走可执行的最优保护路线； 两条都不可执行时 BLOCKED 重试。
  • 防反复损耗：同侧持仓未退出 → 该 token 禁止重挂 Reward BUY； 周期关闭后原有冷却照常生效。对侧买单：在挂 + 新增 ≤ 未配对残差。
  • Merge 未就绪时暂停新开仓：Type3 且开启自动 Merge 时，Merge 运行时 能力未就绪（Relayer 未配置/验证失败/存款地址不符/交易禁用等）→ 不挂新的 Reward BUY；扫描、监控、既有库存退出、既有撤单照常。Type1/Type2 不受影响， Fast Exit 仍可用 Maker/Market 路径。
  • 结果不确定时绝不当失败处理：FOK/Relayer 结果未知 → 周期 BLOCKED/ CLOSING，等对账，绝不「假设失败然后市价卖」。
  • 每次退出都持久记账，退出方式为 MERGE / FOK+MERGE / MAKER / MARKET / MIXED；历史页「库存退出周期」可展开逐腿查看；仪表盘给出「今日 Rewards ＋ 今日库存已实现 PnL ＝ 今日净收益」（奖励未记账时显示待记账，不填 0）。
  • 关闭「启用成交后快速库存退出」即回退 V1 成交后离场行为（兼容/测试用）。

Merge / Relayer 授权

  • 首次配置一次，之后自动加载。在「配置」页的「Merge / Relayer 授权」里填一次 Builder API Key / Secret / Passphrase，凭据会用登录密码派生的密钥 AES 加密后存库； 之后每次登录都会自动解密使用，不再需要 SSH 手工编辑服务器环境变量。
  • Builder 凭据必须在 polymarket.com/settings 的 Builder 页面自行创建， 无法从钱包私钥推导生成。
  • 普通用户无需填写 Relayer URL：默认使用官方 https://relayer-v2.polymarket.com/；高级部署仍可用 PMM_RELAYER_URL 覆盖，缺少它也不会让 Merge 不可用。
  • 「保存并测试 / 重新测试」只做只读验证：本地派生 Deposit Wallet、比对存款地址、 Relayer 认证读 nonce、确认 CLOB 交易可用；不会部署钱包、不会提交 Merge、不会下单。
  • 状态一目了然：未配置 / 已配置未验证 / 验证成功 / 验证失败；钱包列表按钱包独立显示 「Merge 可用」「Merge 已关闭（模板）」「Merge 不可用 · 原因」。
  • 服务器部署仍支持 PMM_BUILDER_API_KEY / PMM_BUILDER_SECRET / PMM_BUILDER_PASSPHRASE 环境变量；UI 加密配置优先，环境变量是回退来源， 两者不会互相覆盖。
  • Relayer API Key 认证是平台的另一种认证方式，本版 UI 暂不开放（KNOWN_LIMITATIONS）。

Merge 参数

  • 启用自动 Merge：默认开启；取消勾选后只关闭该模板的自动 Merge，不影响 Type1/Type2 或 Type3 的常规做市。
  • 最小 Merge 份数：默认 1；配对数量小于它时不提交 Merge。
  • 补边 Merge 最低优势：默认 0.01 USD；只有“FOK 补对侧 + Merge”比受保护直卖至少多回收这么多价值，才选择补全（成交后立即判断，不必等严重亏损）。
  • 低余额触发线（low_balance_threshold_usd）：默认 0，即关闭自动低余额清仓。

重要提示

  • 停止引擎会停止仓位监控；已有仓位需要你自行关注。
  • 本程序不提供网页自更新，也不会自行拉取代码、重置工作树或重装依赖。
  • 任何部署或版本更新都应由管理员在停止引擎后显式执行并验证。
