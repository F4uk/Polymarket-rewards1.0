使用说明

把这套程序怎么跑、每个参数是什么意思，一次讲清楚。看不懂的参数保持默认即可，默认值是按经验调好的——唯独「档位模块」没有默认值，必须自己配，不配就不会挂单。

一、这个程序在做什么

它替你在 Polymarket 上做市，目的是赚交易所发的流动性奖励，而不是赌方向。做法是：在符合条件的市场里，按规则挂买单提供流动性，奖励按你挂单的金额和贴近盘口的程度分配。一旦买单成交、手上有了仓位，程序再按离场规则把仓位卖掉。

整个过程不需要你盯盘：填好钱包私钥、设好参数、点开始，程序就会自己循环扫描、挂单、看守、离场。

二、整套运行逻辑

1. 登录与钱包

第一次打开要设一个登录密码，私钥用这个密码加密后存在本地（AES-256-GCM）。之后每次启动都要先登录，因为解密私钥的钥匙只存在内存里，关掉程序就没了，所以程序不会开机自动跑，必须先登录。

你只需填签名私钥，程序会自动推算出对应的存款钱包地址（Polymarket 的 Safe 地址，真正持有资金的那个），不用手填。

2. 扫描发现市场

程序拉取 Polymarket 当前所有发奖励的市场，先按你在配置里勾选的做市品类白名单过滤（默认做除体育/电竞/天气外的全部，含「其他/未分类」），再用几道门槛筛：

  • 市场日均奖励池要够大（最低奖励金额）。
  • 市场的最低挂单份数必须恰好等于你启用的某个档位模块的档位值，否则这个市场不做（详见下面「档位模块」一节）。

发现是所有钱包共用的，每隔一段时间（默认 4 小时）重新发现一次；下单则更频繁。

3. 选品过滤

发现出来的市场，再按每个钱包绑定的模板逐一过滤：买卖价差不能太宽、当前价要落在你设的单价区间内、距离结算不能太近、这个市场对这个钱包不在冷却期。过了这些才进入挂单。

4. 挑价挂买单

对每个合格市场，程序按你选的挂单模式挑出一个价位，只挂一单：

  • 断层单档（默认）：看整个买单簿相邻价位的最大价差，把市场归到三级之一（宽断层 / 中断层 / 密盘），再从买一往下挑第一个「风险系数超过该级门槛」的价位。挂几份由该市场对应的档位模块决定。
  • 厚墙（v1.0.15 老策略）：找到第一堵挂量够厚的墙，挂在它下面一档。挂几份由「挂单份数」模式决定。

两种模式都只在奖励区间内挂单（断层分级看全簿，是为了发现区间下方的深坑；能挂的价位仍限于区间内）。竞争越小的市场（你能分到的奖励份额越大）越优先下单。整个市场的投入受「单市场最大敞口」和「最大份数」两道闸限制，多个市场同时做也有数量上限。两种模式怎么切、各自要注意什么，见下面「两种挂单模式 · 怎么选、怎么切」。

5. 看守与离场

挂上买单后，看守线程每隔几秒做一轮检查：

  • 成交检测：买单一旦成交就记冷却、撤掉这笔买单的剩余量。
  • 结算保护：一旦有人在 UMA 上对某市场提交结算（该市场随时会定为 0 或 1），立刻撤掉这个市场你所有的买单，避免在结算前被成交、接到要归零的份额。
  • 离场卖出：手上每个仓位维持一笔卖单，按两段式规则定价（见下面「离场逻辑」一节）。
  • 买单收敛：盘口变动后，把现有买单收敛到最新的目标档位（价不对或量不对的撤掉重挂）。
  • 跌出撤单：某市场不再符合条件了，把它上面的买单整体撤掉（持仓仍正常卖出）。
  • 单侧暂停：某个方向已经有仓位了，就只暂停这个方向继续挂买单，另一个方向照常。

重要：止损看守只在引擎运行时有效。停止引擎会撤掉买单、同时停掉看守线程，已有仓位就不再受止损保护。想让止损一直守着，引擎要保持运行。

6. 自动 / 手动两种模式

自动：点「全部启动」后，程序自己循环扫描、下单、看守，不用管。手动：扫描、下单、启动看守分成几个按钮，你一步步自己来，适合想看清每一步的时候。

7. 每个钱包单独配代理

可以给每个钱包填一个 HTTP 代理，填好后这个钱包的所有网络请求都从对应代理 IP 出口，实现按钱包的 IP 隔离。代理连不上时这个钱包本轮会跳过，绝不改用真实 IP 直连。留空就是直连。

8. 自动更新

启动时会检查 GitHub 上有没有新版本，有就提示你下载、校验、静默安装并重启。

档位模块（决定「做哪些市场」和「挂几份」）

Polymarket 每个奖励市场都规定了一个最低挂单份数（20 份、50 份、100 份……），这个数字直接决定了做这个市场的最小本钱和风险。所以挂单参数不是全局一套，而是按最低份额分档配置：

  • 一个模块 = 一个档位值 + 这个档专属的一套参数。在「配置 → 档位模块」里点「+ 添加档位」，填档位值（比如 20），设挂单份数，再配这一档的三个选档门槛、三个高位系数和门槛、金额数值表。
  • 精确匹配，不做区间也不四舍五入：市场的最低份额必须恰好等于某个已启用模块的档位值才会做。启用了 20 档和 50 档，那么最低份额 30 的市场就完全不碰。
  • 挂单份数可以大于档位值：档位值 20、份数填 40，就是在最低份额 20 的市场上挂 40 份（挂得多，奖励份额也大，占用资金相应变多）。份数不能小于档位值，否则拿不到奖励资格。
  • 份数不影响选档：算风险系数时分母用的是市场自己的最低份数，不是你配的份数。份数只决定「挂多少」，不改变「挂在哪一档」。
  • 停用某个模块（取消勾选）＝ 不再做这个档位的市场；下一轮下单时，这些市场上已挂的买单会被整体撤掉（持仓照常卖出）。

没有任何已启用模块能对上的市场，扫描阶段就不会进入合格列表，下单阶段还有第二道拦截。如果一个档位都没配，程序不会挂任何单——仪表盘顶部会持续提示你去配。

两种挂单模式 · 怎么选、怎么切

程序有两套挑选挂单价的策略，在「配置 → 挂单参数 → 挂单模式」里切换。它是模板级的，所以你可以让一部分钱包跑一套、另一部分跑另一套做对比。

看什么相对值：挂量 ÷（最低份数 × 金额数值）绝对值：单档挂量是否超阈值
挂几份档位模块里配的「挂单份数」「挂单份数」下拉：最低合格份额 / 按美元上限 / 全额余额
档位模块全部字段都用只用「档位值」和「启用」，其余全忽略

厚墙的判定细节：1 美分盘看单档挂量是否超过「厚墙阈值」（默认 2000）；0.1 美分盘从买一往下累加，累计超过「累计阈值」（默认 6000）就停。找到第一堵墙就定死：如果那堵墙的下一档超出可挂范围或出了奖励区间，整个市场就不挂，不会再往下找第二堵墙。挂单价必须落在奖励区间内。

切到厚墙（老策略）怎么操作

  1. 配置页顶部选好要改的模板（改哪个模板就只影响绑了它的钱包）。
  2. 「挂单参数 → 挂单模式」选厚墙（v1.0.15 老策略）。页面会把断层那套参数收起来、露出厚墙的参数。
  3. 先别急着保存。去「市场发现」页点几个市场的「展开」，看看预演表里各档的盘口量大概是什么量级。这一步很关键，理由见下面的注意点第 1 条。
  4. 回来把「厚墙阈值」「累计阈值」调到跟你看到的量级相称。
  5. 选「挂单份数」。想完全照 v1.0.15 的默认行为就选最低合格份额。选「按美元上限」的话必须把下面的金额填上，留 0 等于一单都不挂。
  6. 保存。下次引擎启动才生效，已经在跑的话要停掉再启动。

切回断层单档怎么操作

同样先选对模板，「挂单模式」改回断层单档（现行策略），保存，重启引擎。断层那套参数一直都在（切走时只是被隐藏，值没有被清掉），所以切回来不用重新填。

切换时会发生什么

换模式等于换了一套目标挂价。下一轮下单时，程序会把所有对不上新目标的在挂买单撤掉，再按新策略重新挂。如果新策略判定某个市场不挂，那个市场的买单就只撤不挂。所以切换后的头几分钟看到大量撤单是正常的，不是出故障。已经成交的持仓不受影响，照常由离场逻辑看守。

配置注意点（切之前先看这几条）

  1. 厚墙的默认阈值可能对现在的盘口偏高。2000 / 6000 是 v1.0.15 那个年代的值。实际观察到的一个市场，最厚的一档只有 236 份，按 2000 的阈值，这种市场会被判「无档达到阈值」而整个不挂。所以第 3 步的「先看预演」不是走过场：阈值定得比盘口量级高，结果就是一单都挂不出去。
  2. 厚墙模式下档位模块只剩两个字段有用。「档位值」和「启用」决定做哪些市场（市场的最低奖励份额必须恰好等于某个已启用的档位值），其余的挂单份数、三级选档门槛、高位系数和门槛、金额数值表全部不生效。所以切到厚墙后仍然要至少启用一个档位模块，否则一个市场都选不出来。
  3. 「按美元上限」忘填金额 = 全部不挂。金额留 0 时，算出来的份数永远不够最低奖励份额，每个市场都会被跳过。历史页会记下原因，但你可能要过很久才发现。
  4. 厚墙模式不是百分之百的 v1.0.15。监控侧的悬崖复查、实时奖励复查、盘口价差复查仍然生效，它们是独立风控，跟用哪套定价无关。想要纯 v1.0.15 的行为，把「悬崖探测」配成 0。
  5. 断层单档下，实际起作用的主要是规则1 的那两个参数。分级看的是整个买单簿，而买单簿低价区（1 到 8 美分那一带）通常比较稀疏，很容易冒出超过 10 美分的断层，于是大部分市场都会归到规则1。规则2、规则3 的选档门槛和高位系数和门槛虽然能配，但实际触发的机会不多。调参时先调规则1 的。
  6. 数字框不要留空。留空表示「这一项不改」，保存后仍是原来的值，不是「恢复默认」。想改就填具体数字。（唯一的例外是「最长结算天数」，那一项留空的意思是「不限」。）
  7. 两套模式共用的部分不受切换影响：选品筛选、品类白名单、预算与敞口封顶、买单撤改收敛、离场与止损、低余额清仓、每钱包代理、盈亏台账和周报。切换只换「挑哪个价、挂几份」这两件事。

举个例子

场景一：想试试老策略，但不想动现在跑着的钱包。在配置页新建一个模板，把它的挂单模式设成厚墙、配好阈值，然后只把一两个钱包改绑到这个新模板上。其余钱包留在原模板继续跑断层单档。跑几天后到「盈亏」页按钱包对比两边的收益。

场景二：切了厚墙以后一单都不挂。八成是阈值相对盘口太高。去历史页看跳过记录的「原因」列：写「无档达到阈值 2000（扫描范围内最厚 236）」就说明是阈值问题，把阈值调到 200 上下再看；写「悬崖」就是买单下方没支撑被否决了，可以把悬崖探测调大或设 0（它查的是「这一段里有没有买档」，段越宽越容易找到，所以数越大越宽松——调小只会否得更凶）；写「按份数模式 custom 算出的份数不足最低份数」就是第 3 条那个忘填金额的坑。

断层单档选档规则

这是怎么在一个市场里挑出「挂哪一档」的地方，也是策略的核心，慢点看。

  • 分级看全簿，挂单只在奖励区间内：给市场分级（下面第三条）时看整个买单簿，包括奖励区间外的价位——区间下方的深坑正是要防的东西，只看区间内就看不见它。真正能挂单的价位仍只限奖励区间内。
  • 风险系数：某个价位的风险系数 = 该价位盘口挂单量 ÷（这个市场的最低份数 × 金额数值）。金额数值来自该市场对应档位模块里的「金额数值表」，按价格档配（价越高数值越大），价超表的档直接不挂。
    例：最低份数 20，某档价 0.25、盘口挂了 60 张、金额数值 1.5，则风险系数 = 60 ÷（20 × 1.5）= 2.0。价越高分母越大，同样盘口算出的系数越低（越贵的价位要更厚的盘口才够格）。
  • 先给市场分级：看整个买单簿相邻价位的最大价差——>「宽断层阈值」归规则1（宽断层）、≥「中断层阈值」归规则2（中断层）、更小归规则3（密盘）。宽 / 中断层阈值是模板全局的，所有档位共用。
  • 再选一档：用所属级别的「选档系数门槛」（取自该市场对应的档位模块），从买一往下取第一个「风险系数 > 该门槛」的价位，只挂这一档、挂该模块配置的份数；没有任何档过门槛就整个市场不挂。
  • 高位厚度闸门：选档之前先看「断层上方到买一」这一段的风险系数之和够不够。三级各有自己的门槛（在档位模块里配），不够就整个市场不挂。规则1 默认 20；规则2、规则3 默认 0，0 表示不设这道闸。

想看某个市场实际会怎么判，去「市场发现」页点「展开」——预演会显示它归到哪一级、每档的系数、选中哪一档、挂几份，不挂的话也会给出原因。

四、引擎参数（全局，所有钱包共用）

在「配置 → 引擎参数」里改，影响整体节奏。

参数默认含义
扫描间隔30 秒自动模式下两轮下单之间隔多久。
成交检测间隔5 秒看守线程多久检查一次成交和离场。

五、离场逻辑（快速退出：回收资金优先）

Reward BUY 成交进来的库存是做市磨损，不是长期投资。程序不会再让它「套牢等回本」，而是尽快把资金周转回余额、继续赚奖励。整个流程：

Reward BUY 成交
    -> 已有 YES+NO 整对?先 Pair Merge(烧掉等量 YES+NO,换回 1:1 抵押品)
    -> 残差(单侧):
       短 Maker 卖(挂卖一,等待至「最老一笔在持买入 + 等待秒数」)
       |-> 成交 -> 平仓
       |-> 超时 / 触发止损阈值 -> 比价:
              A. FOK 补对 + Merge(回收 = 整对抵押品 − 补对成本)
              B. 受保护 FAK 卖出(带最坏价,绝不成交低于保护价)
           执行回收更优的路线
  • Pair Merge 优先：一旦发现同一市场有 YES+NO 两边的持仓，先合并掉 min(YES, NO) 份整对换回抵押品，残差再走单侧流程。Merge 需要 Relayer 凭证（环境变量），且只在经济上更优时才选 FOK 补对路线 —— 不保证一定合并。
  • Maker 等待：默认 60 秒（配置里可改，0=不等）。等待截止时间由最老一笔在持买入成交的交易所时间戳决定：部分成交、程序重启都不会把倒计时重置。Maker 卖单允许小额亏损，目的是尽快回收资金。
  • 止损阈值跳过等待：亏损达到「配置 → 策略参数」里的止损线（按比例默认 20%，或按固定金额）时，不再等 Maker，立即比价离场 —— 严重亏损绝不停在账上等回本。
  • 受保护 FAK：以「当前买盘深度能全部成交所需的最低买价」作为最坏价提交 FAK 限价卖单，盘口瞬时跳水也卖不穿这个价；深度不足时部分成交可接受，残差下一个监控周期再处理。
  • FOK 补对 + Merge：需要补对侧有足够卖盘深度，且补对后合并的回收必须比直接 FAK 至少多出「最小 Merge 优势」（默认 0.01 USD）。FOK 全成或全不成；延迟确认时绝不重复补对，程序会先对账真实余额/订单再继续。
  • 真实余额永远优先：手工卖出、手工补对、重启中断都以链上实际持仓为准，程序不会凭空重建或重复下单。
  • 成本口径不变：成本仍由真实成交记录 FIFO 加权算出；Merge 会把已确认的整对消耗从持仓成本里扣掉，残仓成本保持正确。算不出成本时程序宁可跳过、不乱卖，并在监控页标红提醒。

Merge 只在链上/Relayer 确认后计入盈亏（盈亏台账「Merge盈亏」列），提交中/失败都不计。旧的两段式离场（挂卖一/挂成本价等回本）在「快速退出整体关闭」（Maker 等待=0 且 Merge 未启用）时仍作为兜底生效。

六、几个要记住的点

  • 不配档位模块就一单都不挂。这是刻意的：挂几份、什么盘口才挂，必须由你按最低份额分档决定。仪表盘顶部会提示哪些模板还没配。
  • 停止引擎会停掉止损看守，已有仓位失去保护。想止损一直生效就别停引擎。
  • 余额在每次下单前都重新读，避免并发成交导致超额。
  • 参数改完，下次启动引擎才生效（已在运行的需要重启）。
  • 监控页出现「裸奔」字样，说明某仓位暂时没有卖单保护（通常是成交记录还没同步，下一轮会自愈），留意一下即可。
